# Opportunity review

## Read

Read the accepted closeout, final spec, `docs/PROJECT-SETUP.md`, the relevant idea/function review, and known limitations. Do not reread all implementation detail unless a follow-up depends on it.

## Assess

Identify only follow-ups supported by user value, evidence, a discovered limitation, or a project goal. For each, summarize outcome, value, dependencies, rough order, and important unknowns. Avoid speculative feature lists and scope already in flight.

## Output

For meaningful feature/milestone work, write `07-opportunity-review.md` in the completed task folder or the workflow-designated location. Mark all recommendations as proposals. If the user chooses one, start a separate `/function-review` record; do not create a spec or branch automatically. Skip this stage for routine fixes unless the user requests it or a clear opportunity emerged.
